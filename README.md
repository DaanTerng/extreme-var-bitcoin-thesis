# Covariate-Conditional EVT for Extreme VaR Forecasting
### A Bitcoin Application

Wing Fong Daan Terng — BSc Econometrics and Operations Research — Vrije Universiteit Amsterdam — June 2026

Python code accompanying my bachelor's thesis on extreme conditional quantile estimation and Bitcoin tail risk. The project combines quantile regression (QR) with extreme value theory (EVT) to forecast one-day Value-at-Risk (VaR), comparing covariate-based forecasts with a GARCH(1,1)-EVT benchmark.

The research examines how nonlinearity and covariate-dependent tail heaviness affect forecast accuracy at the 99%, 99.5%, and 99.9% quantile levels.

## Methods and findings

- **2Stage:** estimates intermediate conditional quantiles using linear QR, followed by Hill tail-index estimation and Weissman extrapolation.
- **3Stage:** estimates a Box-Cox transformation, fits QR on the transformed response, and back-transforms intermediate quantiles before tail extrapolation. The threshold parameter `k` is selected using a moment-based criterion.
- **Benchmarks:** direct QR in simulations and GARCH(1,1) with a Generalised Pareto tail fit in the Bitcoin application. Common-slope estimators are included in the 2012 replication study.

The thesis simulations show that 2Stage can deteriorate under exponential nonlinearity and substantial tail-index variation. 3Stage offers greater flexibility but can be unstable in small samples.

The Bitcoin backtest finds no statistically significant full-sample differences in predictive accuracy. Regime comparisons indicate that GARCH-EVT's advantage is concentrated in the middle nonlinearity regime, while 3Stage outperforms 2Stage in the nonlinear regime at selected quantile levels. See the [thesis report](Thesis_Report_Wing_Fong_Daan_Terng.pdf) for the full results.

## Setup

Use Python 3 in a virtual environment and install the required packages:

```bash
python -m pip install numpy pandas scipy statsmodels matplotlib joblib arch yfinance fredapi
```

Run the commands below **from the repository root**, using `python -m` so that imports from `src` resolve correctly.

Full simulation and backtest runs can be computationally expensive. Parallel routines use `joblib` with `n_jobs=-1`. For a short simulation check, reduce the Monte Carlo replication count in the relevant script.

## Bitcoin application

The supplied `data/btc_data.csv` contains BTC prices, log returns and losses, and candidate covariates. Sources are Yahoo Finance (`BTC-USD`, `LQD`) and FRED (`USEPUINDXD`, `DEXUSEU`, `VIXCLS`, `T10Y3M`, `T5YIFR`). Using the supplied CSV keeps the input sample fixed. Downloading again may change historical values.

Covariate selection uses the 2015–2018 screening sample, examining correlations and comparing out-of-sample quantile losses across candidate predictor combinations. The procedure is implemented in `src/empirical/covariate_selection.py` and described in the thesis. The selected predictors are lagged log return and five-year forward inflation expectations (`T5YIFR`). 

The backtest uses data from 2019 onward, a 500-observation rolling window, and target quantile levels `0.99`, `0.995`, and `0.999`. Forecasts are upper quantiles of log-loss; their negatives are the corresponding return thresholds.

Regimes are defined by variation in QR slopes across upper quantiles, using median and tertile splits. Generate regime labels before running the backtest, then plot the saved forecasts:

```bash
python -m src.empirical.linearity_regime_classification
python -m scripts.empirical.rolling_window_back_test_run
python -m scripts.empirical.plot_var_forecasts
```

The backtest saves `outputs/tables/var_forecasts.csv` and `outputs/tables/backtest_results.txt`. Reported results include average quantile losses, regime-window counts, Kupiec coverage tests, and Diebold-Mariano comparisons overall and by regime.

Close displayed plot windows to allow scripts to finish. The forecast plotting script requires the CSV generated by the backtest.

Optional diagnostics and covariate screening:

```bash
python -m src.empirical.btc_diagnostic_tests1
python -m src.empirical.covariate_selection
python -m scripts.empirical.plot_btc_series
```

To download data again, configure your own `FRED_API_KEY` locally in `scripts/data/data_prep.py`, then run:

```bash
python -m scripts.data.data_prep
```

This replaces the prepared CSV. Regenerate regime labels afterward. The supplied data require no API key.

## Simulation studies

```bash
python -m scripts.simulation.simulation_study_paper
python -m scripts.simulation.simulation_study_2012_parallel
python -m scripts.simulation.simulation_study_2013_parallel
```

The main study (`simulation_study_paper.py`) evaluates QR, 2Stage, and 3Stage, including known-transformation comparisons where available. It is configured for three target levels (`0.99`, `0.995`, `0.999`), sample sizes `500` and `2000`, and 500 Monte Carlo replications.

Results are saved to `outputs/tables/simulation_thesis.csv`, including integrated bias, root integrated mean squared error, relative error (`RIMSE_n`, corresponding to RMSPE), parameter summaries, and valid observation counts.

The 2012 and 2013 studies compare selected methods with published simulation results. The 2012 script evaluates both configured quantile levels. The 2013 script runs **one `tau_n` at a time**; change this setting and rerun to examine another level.

Cases, sample sizes, and replication counts can be adjusted in the scripts. Small replication counts are useful for debugging but are insufficient for comparing Monte Carlo error measures with published tables. Each run replaces its output CSV, so save separate copies when comparing settings.

## Scope and implementation checks

This repository contains the estimator implementations and selected thesis experiments, rather than an automated reproduction of every table. The main simulation implements seven cases. Sensitivity experiments reuse case 4 with alternative values of `sigma`. Reproducing them requires updating `sigma` consistently in the data generator and true conditional quantile function.

The authors’ R reference implementation was used to check the Python estimators on identical simulated datasets and revealed close agreement for 3Stage, while larger differences remained for 2Stage. The Python implementation uses `(n-k)/(n+1)` as the intermediate quantile level, while the R reference uses `1-k/n`. The effect of this difference has not been isolated. The comparison scripts are in `scripts/simulation/checks/`. Generate the shared datasets, then run both implementations from the repository root. The R check requires R and the `quantreg` package.

```bash
python -m scripts.simulation.checks.get_data_sample
python -m scripts.simulation.checks.run_simulation_checks
Rscript scripts/simulation/checks/run_simulation_checks_R.R
```

Keep the sample-size and replication settings consistent across the three scripts.

Extreme-quantile error measures can be sensitive to a few unusually large predictions. The Python runs checked so far show several qualitative patterns reported in the thesis, although some numerical error measures differ substantially. The 2013 replication also shows partial qualitative agreement with the article, but substantial numerical discrepancies remain, particularly in case 1.
